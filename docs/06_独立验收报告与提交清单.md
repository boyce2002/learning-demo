- P0 业务闭环的代码实现完整：`today → attempt → complete → progress`，中途刷新分别恢复 `not_started/attempted/completed`，首答锁定，错误猜想依然能够完成；状态由 SQLite 而非前端模拟。

## 3. 源码检查证据

- `backend/app/services.py`：`record_attempt` 保存首次选择；`complete_day` 使用服务端记录、校验反思、返回最新进度；`compute_streak` 根据参考日倒推，缺今日但有昨日时保留 streak。
- `backend/app/database.py`：`UNIQUE(user_id, local_date)`、`BEGIN IMMEDIATE` 和外键约束提供去重与并发保护。
- `backend/app/clock.py`：正常模式禁用 `demo_date`，演示模式控制 ±30 天范围、按 `Asia/Shanghai` 计算自然日。
- `backend/app/routes.py`：仅在两个演示开关同为真时注册 `/api/dev/reset`。
- `frontend/src/App.tsx`：GET 请求使用 `AbortController` + 递增序号避免日期切换时的过期看板数据覆盖；提交失败保留选项和反思。
- `frontend/src/components/LearningJournal.tsx`：有 `role="dialog"`、`aria-modal`、关闭按钮及遮罩点击关闭；但暂未见 Esc、焦点进入、焦点约束、关闭后归还。
- `frontend/src/styles/tokens.css`：已设置 `prefers-reduced-motion: reduce`，不是缺失项。

## 4. 建议修改：按优先级

### P0：正式交付必须完成

1. **清理交付包**：提交源码、`package*.json`、`requirements.txt`、测试、README、设计说明和截图；排除虚拟环境、第三方依赖、pytest 数据库、dist、缓存、`.env`、真实 SQLite。
2. **完成真实交付形式**：按原题要求提供可访问的 Demo 链接或录屏视频，并在说明中注明演示用户、人工题库、模拟日期与当前产品边界。
3. **公共部署决策**：如果使用公共 URL，先实现访客隔离（匿名 session / 独立数据空间）并彻底禁用不受控 reset；否则采用本机录屏提交，避免共享数据互相覆盖。

### P1：最后一轮适度优化

1. **模态框键盘可用性**：`frontend/src/components/LearningJournal.tsx` + `frontend/src/App.tsx`，在打开时聚焦弹窗、Esc 关闭、Tab/Shift+Tab 不穿透背景、关闭后归还焦点。最好补组件级或浏览器自动化用例。
2. **历史查询竞争条件**：`App.tsx` 的 `openJournal()` 请求未传 `AbortSignal`/请求序号；若在慢网速下打开手记、切换日期、再打开，旧响应可能覆盖当前列表。可复用看板的请求取消/序号模式，在关闭或日期切换时取消。
3. **手工验收**：真机软键盘、逐键 Tab、断网后重试、不同 viewport。通过后录屏。

### P2：可选工程卫生，不影响当前三天作品

- `backend/app/database.py` 的 `with sqlite3.Connection` 自动提交/回滚但不显式 `close()`；建议用 `contextlib.closing` 或封装连接生命周期，保持事务上下文清晰。修改需要确保并发与回滚测试全部保持通过。
- 固定演示日期的 2026-11-05/06/07 不会永久适用：`demo_date_window_days=30`，长期重复演示需按当天重新选择参考日期，而不能永远用 11 月的脚本。优先调整脚本的日期策略，不必改任务分配算法。
- 可在 Git 初始化后提交一次可复现的源码版本并打 tag（如果时间允许）。

## 5. 提交前复核命令（Windows PowerShell）

```powershell
# 在 SparkLab_v0.2 根目录
Set-Location .\backend
..\.venv\Scripts\python.exe -m pytest -q
Set-Location ..\frontend
npm.cmd ci
npm.cmd run build
Set-Location ..
```

若未初始化 Git：

```powershell
git init
git add .
git status --short
# 仔细核对 staged 内容没有 .env、.venv、node_modules、SQLite、测试数据等
git commit -m "feat: complete SparkLab v0.2 learning demo"
```

> `git add .` 只应在 `.gitignore` 内容已确认正确且 staged 检查通过后使用；不必把演示数据提交 Git。压缩源码应使用显式排除项，而非简单压缩整个工作区。

## 6. 录屏建议：不超过 90 秒

1. 首页：用 8 秒解释“不是刷题，是主动探索”。
2. 错误猜想：用 15 秒展示真实反馈，不惩罚答错。
3. 一句话反思：用 15 秒演示完成并点亮星星。
4. F5 刷新：用 8 秒证明后端持久化不是纯前端假数据。
5. 时间舱：用 15 秒展示连续三天与漏学后 streak 的计算。
6. 星光手记：用 10 秒展示真实历史及反思；剩余时间用于结尾阐述技术栈和设计取舍。

**建议最终对面试官传达的主题：**“我们奖励的不只是正确答案，而是学生每天主动思考一次的行为。”
