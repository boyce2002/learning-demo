## 2. 为什么修改

### 无障碍问题

原手记只有 dialog 语义与点击关闭，没有焦点进入、焦点约束、Escape 或焦点归还。键盘用户打开后可能继续操作背景页面，也无法用标准按键稳定退出。修复使用原生 React refs/effect 和 DOM `keydown`，没有引入 UI 框架；监听随组件挂载/卸载，避免重复监听泄漏。

### history 竞态问题

看板请求已有 AbortController + 序号保护，history 请求却会在关闭或切日期后继续写 state。慢网情况下，过去一次打开的响应/错误/finally 可能覆盖当前日期手记，造成“未来历史”视觉泄漏或错误结束新 loading。修复将取消与序号保护独立应用到 history，并在所有退出路径统一失效旧请求。后端仍以 `local_date <= reference_date` 做最终数据边界。

### 依赖风险

最初 `npm ci` 报告 1 high + 1 moderate，来源是 Vite 6.0.5 及其 esbuild。`npm audit` 给出同主版本 6.4.5 修复路径，因此进行小版本升级并完整重跑构建/浏览器，而没有使用 `audit fix --force`。

### 未修改的稳定逻辑

后端首次 attempt 锁定、completion 幂等、6–120 Unicode 校验、streak/累计、历史参考日过滤、Demo 安全开关已由现有测试覆盖，修改它们会扩大最后收尾风险。`database.py` 没有显式 `close()` 的建议仍属 P2；当前 context manager、并发与回滚测试均通过，本轮不碰底层连接生命周期。

## 3. 实现效果

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 打开星光手记 | 焦点位置不受控 | 自动进入顶部关闭按钮 |
| Tab/Shift+Tab | 可穿透到背景 | 在关闭按钮与底部返回按钮间循环 |
| Escape | 无行为 | 关闭 dialog |
| 关闭后 | 不归还焦点 | 触发按钮仍存在时恢复焦点；卸载时不抛错 |
| 重复打开/关闭 | 未管理全局监听 | effect 每次挂载一次、卸载移除 |
| 慢 history 后关闭/切日期 | 旧响应可能覆盖新列表/错误 | 取消请求 + 序号判旧，旧 response/error/finally 均不能写 state |
| AbortError | 可能作为手记错误显示 | 静默忽略 |
| Vite 依赖审计 | 1 high + 1 moderate | 0 vulnerabilities |

P0 业务行为不变：错误猜想仍可完成；反思失败仍保留；完成后进度只采用后端返回；刷新仍恢复 attempted/completed。
