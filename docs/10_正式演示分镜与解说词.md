# SparkLab｜90 秒正式演示分镜与解说词

## 一、录制目标

成片核心句：**SparkLab 奖励的不是答题正确率，而是学生主动提出猜想、理解知识并表达收获的学习行为。**

录制使用本机 `127.0.0.1`、固定演示用户 `demo_student`、人工预置题库和明确标记的模拟日期。所有 streak、累计数和手记必须由真实 UI 调用后端后产生；允许剪掉重复输入和网络等待，不允许手改 SQLite、响应或前端数字。

## 二、录制前真实数据准备

1. 按 README 安装依赖并确认 `pytest`、build、health 均通过。
2. 录屏数据库使用独立文件，例如 `backend/data/sparklab-recording.sqlite3`；该文件被 `.gitignore` 排除。
3. 只在本机设置 `DEMO_MODE=true`、`DEMO_RESET_ENABLED=true`，后端绑定 `127.0.0.1`。
4. 打开页面后确认顶部同时显示“演示用户”和“演示模式/模拟数据”。
5. 点击“重置演示记录”并二次确认，使基准日 D 从 0 天开始。
6. 提前把三句反思放在剪贴板文本文件中，但在镜头里通过 textarea 正常输入/粘贴：
   - D：`我发现先猜再验证，更容易看见自己理解里的差距。`
   - D+1：`我把今天的解释换成自己的话，记住了关键线索。`
   - D+2：`连续三天主动表达，让零散知识变成了可回看的积累。`
7. D 取录制当天页面显示的北京时间；时间舱使用 D、D+1、D+2、D+4。当天题目可能不是苹果题，旁白必须跟随页面实际题目。

建议先录制一条完整的 3–5 分钟源视频，再剪成 90 秒；这样每条历史记录都来自真实操作，同时避免为了卡时长伪造数据。

## 三、90 秒逐镜分镜

| 时间 | 实际页面与画面 | 鼠标/键盘操作 | 中文解说词 | 画面传递的价值 |
|---:|---|---|---|---|
| 0–7 秒 | S1 首页全景：深蓝夜空、月白任务卡、右侧 0 天星轨；顶部保留演示标识 | 鼠标停在任务标题，不点击；轻微下移展示成长卡 | “这是微光实验室。每天五分钟，从一个生活里的小问题开始。” | 克制视觉；任务优先；明确模拟数据边界 |
| 7–15 秒 | S2 猜想页 | 点击“开始今天的探索”；用 Tab 聚焦第一个选项，按空格选择；点击“揭晓答案” | “它不会先把答案递给学生，而是要求先做出自己的判断。” | 主动提取先于答案曝光；键盘可用 |
| 15–25 秒 | S3 错误猜想反馈与知识解释 | 停留在“猜想不同”、正确答案、解释和关键发现区域 | “即使猜错，系统也诚实说明不同，不扣分、不惩罚，而是把错误变成理解的起点。” | 温和但不虚假；奖励探索过程而非正确率 |
| 25–36 秒 | S4 一句话收获 | 点击“写下今天的发现”；粘贴 D 反思；让字符计数短暂停留；点击“点亮今天的星星” | “只有用自己的话留下收获，今天的学习才真正完成。” | 反思是完成条件；不做 AI 假评分 |
| 36–46 秒 | S5 点亮完成页与真实进度 | 展示点亮动画、保存的原文反思、streak 1/累计 1 | “星星代表的不是答对，而是完成了一次猜想、理解和表达。” | 奖励完整学习行为；进度来自后端 |
| 46–54 秒 | 刷新后的 S5 静态恢复 | 按 `Ctrl+R`；等待同一反思与 1 天进度恢复 | “刷新后状态仍然保留，因为 attempt、反思和进度都写入 SQLite，而不是前端假数据。” | 真实全栈持久化；刷新可恢复 |
| 54–68 秒 | S7 演示时间舱，D+1 与 D+2 的完成蒙太奇 | 点击“+1 天”“+2 天”；各保留一次选择、提交和完成页的 1–2 秒片段；剪掉重复输入等待 | “演示时间舱只用于本机功能演示。通过同一套真实接口连续完成三天，streak 增长到 3。” | 模拟日期透明；统计仍由后端真实计算 |
| 68–77 秒 | D+2 成长卡，然后切到 D+4 | 先定格 streak 3/累计 3；点击“+4 天”，定格 streak 0/累计 3 | “跳过一天后，连续天数诚实归零，但累计学习不会消失。” | streak 不制造焦虑；累计尊重历史投入 |
| 77–86 秒 | S6 星光手记三条倒序反思 | 点击“查看我的星光手记”；用 Tab/Shift+Tab 展示焦点环；按 Escape 关闭后再打开定格列表 | “星光手记把抽象数字变成学生真正表达过的知识痕迹。” | 长期积累可回味；dialog 键盘可用 |
| 86–90 秒 | 首页或手记与星轨同框，品牌收尾 | 鼠标移开，不再操作 | “SparkLab 奖励的不是正确率，而是每天主动思考一次。让好奇心，慢慢发一点光。” | 强化产品核心命题 |

## 四、拍摄与剪辑设置

- 推荐 1920×1080、浏览器缩放 100%、30fps、H.264、8–12 Mbps；鼠标指针可见。
- 系统通知、聊天弹窗和浏览器书签栏提前关闭；不要录入终端里的本机用户名或路径隐私。
- 录制前预热首页、health 与静态资源；依赖安装在录制前完成，录制过程不依赖外网。
- 每次点击后等待按钮 loading 消失再进入下镜；成片通过硬切或 150–250ms 淡化剪去等待，不加会掩盖 UI 的夸张转场。
- 输入反思可粘贴，但保留 textarea、字符计数和提交动作；D+1/D+2 的重复过程可做 2–3 个短切镜头。
- 音频优先后期配音；环境噪声大时先录干净画面，再按本表逐句配音。

## 五、故障预案

| 风险 | 录制前预防 | 发生时处理 |
|---|---|---|
| API 未启动 | 先访问 `/api/health`，确认 `status=ok` | 停止录制，重启后端；不要把错误页剪成成功状态 |
| 页面已有旧记录 | 使用独立录屏 DB，并通过 UI 的二次确认 reset | 重新 reset 后从 D 开始；不要直接删表或改数值 |
| 日期超出窗口 | 始终用当天 D 的快捷按钮 D/D+1/D+2/D+4 | 不手输旧示例日期；重新加载当天基准日 |
| 请求等待 | 本地服务预热、关闭无关软件 | 等真实响应完成；后期剪掉等待，不能伪造响应 |
| complete 失败 | 录制前跑 smoke test，保留反思剪贴板 | 展示文本仍在，恢复 API 后重试；必要时重新录该镜头 |
| streak 不符合预期 | 录制源素材时按 D、D+1、D+2 顺序真实完成 | 重新检查 reference date；不得手改数据库统计 |
| 录屏中出现 favicon 404 | 不打开 DevTools 控制台镜头 | 不影响业务；如需展示 Network，仅过滤业务 API |

## 六、必须说清的模拟边界

建议在 54 秒处原句说明：

> “这里切换的是明确标注的模拟日期，只用于演示连续学习计算；每条 attempt、反思和完成记录仍通过真实后端写入。”

避免使用“真实学生已经连续学习三天”“系统分析了学生能力”等措辞。准确说法是“固定演示用户的模拟日期记录”“人工预置题库”“真实接口与 SQLite 持久化”。
