## Step 6-A：公网匿名访客数据隔离（必做）

当前源码的 `backend/app/services.py` 使用全局常量 `DEMO_USER_ID = "demo_student"`，所有访客共用 SQLite 数据；不能直接公网开放。

- 采用**服务端可信的匿名会话身份**：后端签发不可预测的会话标识，以 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 维持访客身份，同源 HTTPS 使用；禁止直接相信前端传来的任意 user_id。生产环境提供持久化签名密钥，并处理签名校验或采用服务端映射，避免 cookie 伪造/串号。
- 业务方法显式接收已验证的 visitor/user id，在全部 `SELECT`、`INSERT`、`UPDATE`、`DELETE` 中按当前访客过滤；保留 UNIQUE 约束、事务、幂等与 streak 算法。
- Cookie 由后端设置，浏览器端 fetch 同源发送。评估跨站请求写入风险：至少检查 `Origin`、约束允许的来源、设置 SameSite，必要时加入 CSRF token；不要把 CORS 当成 CSRF 防护。限制请求大小和写入频率，保护共享服务免受滥用。
- 开发与测试环境保持可注入、可复现的访客上下文；新增测试验证两个独立浏览器/会话的 today、attempt、completion、progress、history 完全隔离，不能通过传入用户 ID 越权读取或清除另一人的数据。
- 不要清空已有本地数据，更不要把现有示例记录作为实际访客数据展示。迁移/兼容策略须说明。

## Step 6-B：可评审的在线演示体验（必做）

- **公开页面仍须完整走真实后端写入流程**，不得把静态图或本地假状态当成完成记录。
- 显眼但不喧宾夺主地提示：`演示体验｜题目为人工预置；学习日期和成长记录可模拟，不代表真实学生数据。`
- 需要让评审在一次访问中看到成长进度。采用**每访客独立的演示时间舱**：允许在受限时间窗口内切换日期、完成 D / D+1 / D+2，再查看 streak；但不能开启当前无身份鉴权的全局 `/api/dev/reset`。若提供“重新体验”，只能重置**当前访客的体验数据**，并额外设置来源校验/防 CSRF、速率限制。不得提供全库删除功能。
- 明确区分“真实今日日期”和“模拟学习日期”；首次进入页面有清楚的体验引导。模拟日期只改变该访客本次演示参考日，不得伪造真实学习统计。
- 保持既有视觉、S0–S7、请求竞态和无障碍行为；不加入登录、LLM、支付、分析追踪等无关模块。

## Step 6-C：单域 HTTPS 部署（必做）

- 根据项目现状提出并实施一个部署方案：前端静态资源 + `/api` 同域代理到 FastAPI，确保刷新、Cookie 与路由均有效。优先最少服务、最少配置。若前后端必须分域，需要阐明 credentials、CORS、SameSite、CSRF 的准确配置和验证步骤。
- SQLite 只能放在有**持久化磁盘**的实例上；若目标平台是临时文件系统，则换用可靠的持久数据库，并说明迁移。禁止把 DB 或会话密钥放入代码库。
- `DEMO_RESET_ENABLED` 的**全局 reset 路由**在公网必须禁用/不注册，且文档中明确区别于当前访客范围重置。不要将本地测试用调试接口暴露公网。
- 加入最小健康检查和运行日志（不输出 Cookie、反思全文或秘密），前端、后端异常给出友好提示。检查 HTTPS、移动端加载、跨会话隔离、空白访客初始态、刷新恢复、不同日期隔离和持久化重启。
- 若本环境没有云平台权限/凭证、域名或网络部署能力：**不要捏造链接或称部署成功**。提供平台无关的可复现部署指南、必要配置模板和明确待用户执行的最少步骤；部署/接入账号必须由用户自行授权。
